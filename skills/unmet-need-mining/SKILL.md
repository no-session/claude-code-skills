# Skill: Unmet Need Mining (Indie Hacker / Bootstrap Edition)

## Purpose

Systematic discovery of **bootstrap-scale product opportunities** by lurking where target users complain in public — Reddit, app store reviews, Trustpilot, G2, niche forums, Twitter/X, Hacker News, YouTube comments, Indie Hackers, Discord and Slack communities.

The goal is to turn raw, scattered complaints into **qualified wedge hypotheses** sized for a one-person or small team — without having to interview anyone yet.

This skill is optimized for two tracks. **VC-scale ideas are explicitly out of scope** (see Anti-Patterns).

### Track A — B2B Micro-SaaS
- **Pricing:** $50–$500/mo per customer
- **Target customer count:** 100–1,500 paying customers
- **Ramen-profitable at:** ~$10k MRR (≈100 customers @ $100/mo)
- **Calm Company territory:** $50k–$200k MRR ($600k–$2.4M ARR)
- **Patrick McKenzie (patio11):** "Boring B2B SaaS is undervalued — charge more for vertical pain."
- **Examples in spirit:** ConvertKit (creators), Bannerbear (image automation API), SavvyCal (scheduling), Drip in early days (DTC email), Wave Accounting in early days (SMB books)

### Track B — Prosumer One-Person Tools
- **Pricing:** $10–$50/mo subscription, or $20–$200 one-time
- **Target customer count:** 500–10,000 paying customers
- **Ramen-profitable at:** ~$5k MRR (≈250 customers @ $20/mo)
- **Pieter Levels territory:** $20k–$100k MRR
- **Examples in spirit:** DevUtils.app (Tony Dinh — Mac dev utilities), NomadList / RemoteOK (Pieter Levels), CleanShot X, niche Chrome extensions, focused iOS utilities

Hand off to other skills once you have a candidate:

- **`office-hours`** — once you have a candidate, pressure-test whether it's worth building
- **`product-strategy-memo`** — once you've picked a direction, build the strategy
- **`product-management`** — once you're building, write the PRD

> **Inline glosses** (use when teaching the user):
> - **Micro-SaaS** — a SaaS designed to be run by 1–3 people, targeting a narrow audience, profitable at <2k customers. Term popularized by Tyler Tringas ~2014.
> - **Wedge** — the narrowest possible first product that gets you a beachhead. In bootstrap context: usually a single workflow for a single persona, never a "platform."
> - **WTP** — willingness to pay. Bootstrappers care about WTP more than reach. This is the inversion of the VC mindset.
> - **Stair-step approach** — Rob Walling's three-rung path: (1) one-time product or simple SaaS in a niche → (2) recurring micro-SaaS → (3) larger SaaS. Each rung funds the next.
> - **Calm Company** — Tyler Tringas's framing for low-burn, profitable, founder-owned businesses ($1M–$10M ARR, no VC). The opposite of blitzscaling.
> - **JTBD** — Jobs-to-be-Done. Frame complaints as "the user is trying to get *job X* done."
> - **Sales Safari** — Amy Hoy's coinage. The original "go where they complain, read everything, take notes" method that this skill is built on.

## When to use this skill

- Looking for a B2B micro-SaaS or prosumer tool idea, no specific direction yet
- Validating whether a vertical pain you suspect is real, frequent, and affordable to solve solo
- Pre-customer-discovery: building a hit list of pains BEFORE talking to people
- Looking for adjacent vertical opportunities in a market you already know
- Looking for a wedge into a category where horizontal tools (Notion, Airtable, Excel) are being bent for vertical use cases
- Generating a backlog of bootstrap-shaped ideas to filter through `office-hours`

**Not this skill:**

| Situation | Use instead |
|---|---|
| You already have an idea and want to pressure-test it | `office-hours` |
| You're ready to talk to users to validate | The Mom Test (book/method — outside this skill) |
| You're past PMF and optimizing strategy | `product-strategy-memo` |
| You're scoping a feature inside an existing product | `product-management` |
| You're looking for a VC-fundable startup | Wrong skill — bootstrap economics differ; see Anti-Patterns |

## Pick your track first

Decide A or B *before* you start mining. They use different sources, pain phrases, and ARPU calibration. Mixed-track clusters score badly because they're usually two different opportunities pretending to be one.

| | **Track A — B2B Micro-SaaS** | **Track B — Prosumer Tools** |
|---|---|---|
| **Audience** | Ops / finance / legal / trades / HR / RevOps; vertical roles in SMB or mid-market | Devs / designers / creators / marketers / hobbyists with disposable income |
| **Best sources** | G2, Capterra, Reddit (r/sysadmin, r/humanresources, r/RealEstateInvesting, vertical subs), Glassdoor "cons", niche industry forums, Indie Hackers B2B success stories | App Store / Play Store / Chrome Web Store, Indie Hackers, Hacker News, Twitter/X, YouTube tutorial comments, prosumer subreddits, Discord communities |
| **Best pain phrases** | "We still track [X] in spreadsheets / Notion / Airtable", "the [department] software is from [old year]", "we built a custom internal tool for", "[incumbent] is too expensive for our size" | "I wish there was an app for", "is there a Chrome extension", "I built a script to", "[tool] doesn't have [feature]", "tried [product] but it doesn't [specific]" |
| **WTP signals** | Already pay for adjacent SaaS ($X00–$X,000/mo budget exists); manual VA labor; spreadsheet hell; expensive incumbent ("we'd pay if it was half the price") | Already pay for tools in the workflow ($5–$50/mo each); buy templates, courses, presets; tip creators; have Patreon subscriptions |
| **Wedge formula** | "[Vertical persona] can't easily [job], currently uses [bent horizontal tool], would pay $50–$500/mo for [narrow vertical workflow]" | "[Prosumer persona] can't easily [task], currently uses [hack/script/manual workflow], would pay $10–$50/mo or $20–$200 one-time for [polished single-purpose tool]" |
| **Ramen profitable at** | ~100 customers @ $100/mo = $10k MRR | ~250 customers @ $20/mo = $5k MRR |
| **Beware** | Long sales cycles in enterprise; bigger contracts ≠ better business for solo founder | Low-WTP audiences (students, hobbyists who won't pay); copycat risk on App Store |

You can run both tracks in parallel — just score them separately. The rubric weights reach and WTP differently per track.

## The workflow

```
1. Pick a watering hole    →  target audience + 1-3 sources (informed by track)
2. Cast a search net       →  structured queries on pain phrases (track-specific)
3. Capture verbatims       →  structured table, raw quotes only
4. Cluster by JTBD         →  group pains by underlying job
5. Score                   →  Pain × Frequency × WTP × Reach × Solution Gap (bootstrap-weighted)
6. Synthesize a wedge      →  track-specific formula, realistic ARPU
7. Counter-validate        →  rule of three: 3+ unrelated voices, same words
8. Decide                  →  pursue / park / kill — AND kill VC-bait shapes
```

### Step 1 — Pick a watering hole

You can't mine "the internet." Pick **one audience** and **1–3 sources** where they congregate publicly. Arvid Kahl's *Embedded Entrepreneur* move: depth beats breadth.

A watering hole is a triple: `(audience, source, expected pain density)`.

See **`templates/sources-playbook.md`** for source-by-source how-to-mine details, including the bootstrap-specific shortlist (MicroAcquire / Acquire.com listings, Indie Hackers product pages, TinySeed portfolio, Failory, BuiltWith).

**Rule:** if you can't name the audience in a single sentence ending in a job title, vertical, or hobby with disposable income, you haven't picked one yet. "People who use computers" is not an audience. "Solo bookkeepers serving 5–30 small business clients" is. "Hobbyist 3D printer owners who run a Bambu X1C" is.

### Step 2 — Cast a search net

Use **pain phrases** — patterns that almost always signal an unmet need. Run them as Google site-searches against each source. The Pain Phrase Library below is the highest-leverage table in this skill.

For Reddit specifically, **gummysearch.com** is purpose-built and worth the cost if mining seriously. **F5Bot** does free keyword alerts. **BuiltWith** lets you reverse-engineer what tools a competitor's customers use — find users of incumbent → mine their complaints elsewhere.

### Step 3 — Capture verbatims

**Capture quotes, not summaries.** Exact words become your headlines, landing-page copy, ad targeting, search keywords. Paraphrasing destroys this asset.

Use the table in **`templates/capture-table.md`**. Minimum columns:

| Source URL | Verbatim quote | Persona signal | Frequency signal | WTP signal | Current workaround |

Aim for 30–50 verbatims before clustering. Less than 20 and you're pattern-matching on noise.

### Step 4 — Cluster by JTBD

Group verbatims by **underlying job**, not surface feature. Two complaints — "I wish [tool] had Slack integration" and "I have to copy-paste from [tool] into our team chat every morning" — are the same JTBD: *get [tool]'s output in front of my team without manual work*.

Frame each cluster as: **"When [situation], I want to [motivation], so I can [outcome]."**

Aim for 3–8 clusters from 30–50 verbatims.

### Step 5 — Score

Use the rubric in **`templates/evaluation-rubric.md`**, calibrated for **bootstrap economics** — small concentrated reach + high WTP wins, not "huge addressable market."

Quick version, 1–5 per dimension:

| Dimension | Bootstrap lens |
|---|---|
| **Pain intensity** | Caps, swearing, "I hate", switching threats, multi-paragraph rants |
| **Frequency** | Daily/weekly mentions vs. one-offs across months |
| **WTP signal** | Already paying for incumbents/workarounds/freelancers/Zapier hacks. **Most important dimension for bootstrappers.** |
| **Reach** | **1k–10k addressable in a defined channel = ideal.** >100k = will attract VC-backed competitors. <500 = math doesn't close at target ARPU. |
| **Solution gap** | Horizontal tool bent for vertical use (Notion-as-CRM for X, Airtable-as-PMS for Y) = goldmine. One vocal incumbent with vocal haters = good. Greenfield in a hot space = will attract competition fast. |

### Step 6 — Synthesize a wedge

For each top-scoring cluster, write **one sentence** in the track-specific shape.

**Track A (B2B micro-SaaS):**
> **[Vertical persona]** can't easily **[do job]**, so they currently **[bent horizontal tool / workaround]**, and would pay **$50–$500/mo** for a tool that **[narrow vertical workflow]**.

**Track B (Prosumer):**
> **[Prosumer persona]** can't easily **[do task]**, so they currently **[hack / manual workflow / DIY script]**, and would pay **$10–$50/mo or $20–$200 one-time** for **[polished single-purpose tool]**.

Examples:

> *(Track A)* Independent insurance brokers running 50–500 active client policies can't easily track which clients are due for annual renewal review, so they currently maintain a color-coded Google Sheet they update manually each Monday, and would pay $80–$150/mo for a tool that pulls policy renewal dates from their AMS, generates the weekly call list, and sends auto-reminders with one-click logging.

> *(Track B)* Indie game devs running playtests on itch.io can't easily collect structured feedback from testers without spamming them with Google Forms, so they currently use a Notion database + manual reminders, and would pay $19/mo (or $99 one-time) for a tool that generates per-build feedback forms, deduplicates testers, and shows a heatmap of where playtesters drop off.

The sentence should be so specific that the persona, hearing it, would say *"yes, that's exactly me."*

### Step 7 — Counter-validate (rule of three)

For each wedge, find **3+ unrelated voices** describing the same pain in **similar words**. If you can't, the cluster was an artifact of you wanting it to be real.

Three real signals beats thirty plausible ones. Cheapest validation step in the entire workflow.

Bonus counter-validation: search MicroAcquire / Acquire.com for sold businesses with similar wedge shape. If a $200k-ARR business with this shape already sold for 3–4x, you have proof the market closes.

### Step 8 — Decide

| Pain × Freq × WTP | Reach | Verdict |
|---|---|---|
| High / High / High | 1k–10k concentrated | **Pursue** — ideal bootstrap shape; hand off to `office-hours` |
| High / High / High | 10k–100k | **Pursue if you can move fast** — risk of VC-backed competitor entering |
| High / High / High | <1k | **Maybe** — only if ARPU can be $500+/mo (Track A vertical only) |
| High / Low / Mid | Any | **Park** — re-mine in 3–6 months |
| Mid / High / Low | Any | **Vitamin trap** — kill or radically reframe |
| Any | Locked (regulated, distribution-gated) | **Kill** — not for solo founder |
| **Any** | **Requires VC scale to monetize** | **Kill — wrong skill** (see Anti-Patterns) |

Output = a ranked shortlist of wedge sentences with evidence links. Feed top 1–3 into `office-hours`.

The single most reusable artifact in this skill. Copy-paste into Google with `site:` operators.

### Universal (both tracks)
| Phrase | What it signals | Strength |
|---|---|---|
| "I wish there was" | Unmet need, problem-aware | High |
| "Is there a tool that" / "Is there an app that" | Actively searching, ready to buy | **Very high** |
| "Looking for an alternative to [product]" | Switch intent, incumbent failing | **Very high** |
| "I would pay for" / "I'd pay $X for" | Direct WTP statement | **Very high** |
| "I built a [spreadsheet / script / Zap] to" | DIY workaround — pre-qualified buyer | **Very high** |

| "Manually" / "by hand" / "copy-paste" | Automation opportunity | High |
| "Anyone know how to" + repeated | Workflow gap, no good answer | Medium |
| "Does anyone else" + complaint | Looking for validation, community pain | Medium |

## Anti-patterns — VC-bait shapes (auto-kill for bootstrappers)

These shapes work for venture-funded teams and fail for solo founders. If a cluster maps to one of these, **kill it regardless of pain score**.

| Shape | Why it kills bootstrappers |
|---|---|
| **Two-sided marketplaces** | Need supply AND demand from day one — chicken-and-egg requires capital to subsidize one side |
| **Pure network-effect / social products** | Value scales with user count; below threshold = worthless |
| **Ad-supported consumer** | Needs millions of MAUs to monetize. You don't have a CAC budget for that. |
| **Enterprise sales (>$25k ACV)** | 6–18 month sales cycles, founder = salesperson, can't build while pitching |
| **Hardware** | Capital-intensive, supply chain, returns, support burden |
| **"Lower the price of [commodity]"** | Race to bottom; margins compress; no moat |
| **Markets dominated by well-funded competitors** | They'll outspend you on CAC, integrations, and brand. Pick markets they consider too small. |
| **"AI wrapper" with no audience moat** | LLM costs eat the margin; next model release commoditizes you |
| **Anything requiring regulatory clearance** (PHI, banking, securities) | Multi-year compliance burden before first dollar |
| **Audiences who refuse to pay** (students, pre-monetization "creators", unfunded hobbyists) | Free vitamin trap |

These are real opportunities — just not for you with this skill. Note them and move on.

## Positive signals — bootstrap goldmines

The inverse: shapes that work *especially well* at bootstrap scale.

| Shape | Why it works |
|---|---|
| **Vertical SaaS where horizontal tools are bent** | Notion-as-CRM-for-real-estate, Airtable-as-PMS-for-clinics, Excel-as-ERP-for-trades. Proven WTP for the bent tool = pre-qualified market for the purpose-built one. |
| **Internal-tools-as-a-service** | "We built this for our company and others want it." (ConvertKit started as a creator's internal tool.) |
| **Long-tail features incumbents won't build** | $1B incumbents won't prioritize features that only matter to a 5k-customer segment. Build there. |
| **Disenfranchised user bases** | When a beloved tool gets acquired and degraded (or shut down), its users become an instant audience. Watch acquisitions, post-mortems, "X is dead, what's the alternative?" threads. |
| **Hobbyist niches with disposable income** | Audio engineers, indie game devs, woodworkers, ham radio operators, board gamers, audiophiles, real estate investors, sim racing, RV travelers, knife makers, photographers, indie filmmakers |
| **Adjacent to an existing platform with proven WTP** | Tools FOR Substack writers, FOR Shopify merchants, FOR Notion users, FOR Etsy sellers, FOR Roam Research users. Distribution + qualified buyers built-in. |
| **Workflows currently done by a freelancer / VA** | If people pay $300–$2,000/mo for someone to do X manually, you can sell a $50–$200/mo tool that does 80% of X. |
| **Boring B2B verticals** (patio11) | Plumbers, dental offices, short-term rental hosts, accounting firms, nonprofits, churches, fitness studios. Underserved by Silicon Valley, high WTP, sticky. |

## Common mistakes

- **Mining for ideas you've already decided to build.** Confirmation bias surfaces what you want to see. Mine the audience first, let the cluster pick the idea.
- **Summarizing instead of quoting.** Verbatims are the product. Paraphrasing destroys positioning, copy, and search keywords.
- **One source.** Reddit-only mining biases toward Reddit demographics. Triangulate with at least one non-Reddit source per audience.
- **Skipping the rule of three.** One vivid complaint feels like a market. It isn't.
- **Mining solved problems.** If three well-funded competitors exist and customers seem mostly happy, the gap is small. Look for "many bad solutions" or "horizontal tool bent for vertical" instead.
- **Optimizing for sexy.** Boring B2B (invoicing for plumbers, scheduling for dental offices, compliance for short-term rental hosts) beats consumer apps for bootstrappers. Don't filter "unsexy" out.
- **Going too narrow without WTP proof.** A 200-person niche only works if ARPU can be $500+/mo. Below that, the math doesn't close.
- **Going too broad.** "A better CRM" or "a better project management tool" attracts VC competition. Pick a vertical.
- **Chasing hot AI/LLM spaces.** Greenfield in a hot category attracts capital faster than you can ship.

## Red flags (false positives)

| Signal | Why it's misleading |
|---|---|
| One vivid rant with hundreds of upvotes | High visibility ≠ high frequency. Could be cathartic, not commercial. |
| "I wish X was free" | Negative WTP. Walk away. |
| Pain from power users only | Doesn't generalize; market may be tiny |
| Complaint about a feature already on the incumbent's public roadmap | Window closing fast |
| Pain in a regulated or distribution-locked space | Kill for solo founder |
| Audience is "creators" / "hobbyists" / "students" without proven WTP | Free vitamin trap |
| Complaints from a single Discord echo chamber | Audience too narrow OR unrepresentative |
| Hot AI/LLM space with multiple VC-funded incumbents | Race you can't win solo |
| "Why doesn't someone build [obvious thing]" with no replies | Possibly already built — search before you build |

## Quick handoff

When the skill completes, output to the user:

1. **Top 3 wedge sentences** in the desperate-specificity format (Track A or B clearly marked)
2. **Evidence**: 3+ verbatim quotes per wedge, with source URLs
3. **Score table** showing Pain / Freq / WTP / Reach / Solution Gap for each
4. **Bootstrap math check**: customer count × ARPU needed for ramen profitability ($5k–$10k MRR); flag if either number looks unrealistic
5. **VC-bait check**: confirm the wedge doesn't map to any auto-kill shape
6. **Recommended next step**: usually "feed wedge #1 into `office-hours`"

That hand-off is the deliverable. Don't strategize, don't write a PRD, don't speculate on pricing beyond the ARPU band. Just surface what the audience said, which clusters cleared the rule of three, and which are bootstrap-shaped.
